# Dataset Report — COCO-Search18 Working Subset for GazeAgent

**Project:** Human vs. MLLM visual exploration under foveated search.
**Scope of this report:** the *dataset* — how the COCO-Search18 source data was acquired,
structured, stratified into a frozen working subset, exported, and characterized — together
with the design choices behind each step and their rationale.

> **What this report does *not* cover.** The study's eventual headline — how MLLM agents
> explore relative to humans — requires the foveation renderer, the agent harness, and model
> runs, **none of which exist yet**. Every number here describes the *human reference data and
> the constructed stimulus subset*, not agent behaviour. Agent↔human comparison is future work
> (see §10). No agent results are presented or implied.

All quantities are generated by [`scripts/analyze_subset.py`](../scripts/analyze_subset.py)
into [`figures/analysis_stats.json`](../figures/analysis_stats.json), the single source of
truth; the figures and tables below are rendered from it and are free to regenerate offline.

---

## 1. Overview

[COCO-Search18](https://sites.google.com/view/cocosearch/) is a laboratory-quality eye-tracking
dataset of **goal-directed visual search**: 10 people searched for each of **18 target-object
categories** in natural COCO scenes, under two regimes —

- **Target-present (TP):** the target is in the image; the searcher fixates and reports it.
- **Target-absent (TA):** the target is *not* in the image; the searcher must decide it is
  absent and stop — the key dependent variable for our stopping analysis.

We use these human scanpaths as the **reference behaviour** against which MLLM agents will
later be compared. This report documents the data side of that comparison.

---

## 2. Source dataset

| Property | Value |
|---|---|
| Categories | 18 (bottle, bowl, car, chair, clock, cup, fork, keyboard, knife, laptop, microwave, mouse, oven, potted plant, sink, stop sign, toilet, tv) |
| Images | 6202 natural COCO scenes |
| Subjects | 10 per image |
| Fixations | ~300,000 search fixations total |
| Conditions | target-present (TP) and target-absent (TA) |
| Canonical frame | all stimuli resized to **1680 × 1050 px** (zero-padded, aspect ratio preserved); **all gaze coordinates live in this frame** |

**Splits and the withheld test set.** COCO-Search18 ships `train` and `validation` fixations;
the **test-split fixations are withheld** by the authors for a benchmark track. There are two
public partitions: `split1` (the paper's train/valid split) and `split2` (train = COCO-2014
train, valid = COCO-2014 val); the test *images* are identical across both. We use `split1`.

**Citation.** Yang, Z., Huang, L., Chen, Y., Wei, Z., Ahn, S., Zelinsky, G., Samaras, D., &
Hoai, M. (2020). *Predicting Goal-directed Human Attention Using Inverse Reinforcement
Learning.* CVPR, 193–202.

**Fixation record schema (raw, preserved losslessly):** `name`, `subject`, `task`,
`condition`, `bbox` [x,y,w,h] (TP only — the target), `X[]`, `Y[]`, `T[]` (fixation x / y /
duration sequences incl. the initial centre fixation), `length`, `correct`, `RT` (TP) /
`fixOnTarget` (TA), `split`.

## 4. Clutter acquisition (COCO instance annotations)

The stratification needs a **clutter** measure defined as the **number of object instances per
image**. COCO-Search18 provides only the *single* target `bbox`, so object counts require
COCO's instance annotations — which were **not present anywhere on the system**. We therefore
downloaded the COCO-2017 instance annotations
([`scripts/download_coco_annotations.sh`](../scripts/download_coco_annotations.sh), idempotent):

| File | Images | Annotations |
|---|---|---|
| `instances_train2017.json` | 118,287 | 860,001 |
| `instances_val2017.json` | 5,000 | 36,781 |

COCO-Search18 filenames are raw COCO ids (`000000478726.jpg` → `478726`); 2014 and 2017 share
identical per-image instance counts, and the 2017 trainval union covers every id. **Coverage
of our validation pool was 100%** (0 images missing, 0 with no annotations).
**Clutter = total instance count for the image** (iscrowd regions counted as 1).

## 5. Subset construction

**Goal.** A frozen, seed-reproducible, stratified subset that all downstream work runs on,
balanced across the factors that drive search difficulty.

**Strata (from the locked spec):**
- **TP:** category (18) × eccentricity {near, far} × clutter {low, high} = **4 cells/category**,
  target **8/category (2/cell)**.
- **TA:** category (18) × clutter {low, high} = **2 cells/category**, target **8/category
  (4/cell)** — no eccentricity, since an absent target has no location.

**Pool = validation split.** Test fixations are withheld, so validation is the held-out
official partition. Both TP and TA provide a validation set of 326 images (11–29/category).

**Definitions.**
- *Eccentricity* = Euclidean distance of the target-bbox centre from the image centre in
  canonical normalized coordinates (`cx/1680`, `cy/1050`).
- *Clutter* = COCO object-instance count (§4).
- *Bin thresholds* = **per-category medians** (each category splits ~50/50 near/far and
  low/high), documented per category below.

**Selection** ([`scripts/build_subset.py`](../scripts/build_subset.py)): group fixations by
`(category, image)` → keep only images with **exactly 10** human scanpaths (a strict
human↔human ceiling later) → assign per-category-median bins → seeded
`np.random.default_rng(0)` samples the target count per cell. Under-filled cells take all
available and **log the shortfall** (no silent capping); an optional `backfill` flag (default
off) can top up from the fullest same-category cell.

## 6. The frozen subset

**Size: 141 TP + 144 TA = 285 images**, each with all 10 human scanpaths (1410 + 1440
scanpaths). TA is perfectly balanced (4/4 per category); TP reaches the full 8 for 15
categories and 7 for three small ones.

![Per-category balance by stratum](../figures/fig_category_balance.png)

![TP stratum occupancy](../figures/fig_stratum_heatmap.png)

**Logged shortfalls** (in [`data/subset_manifest.json`](../data/subset_manifest.json)): three
TP cells held only one candidate where two were wanted —

| category | cell | wanted | available |
|---|---|--:|--:|
| bowl | far-high | 2 | 1 |
| laptop | near-high | 2 | 1 |
| oven | near-high | 2 | 1 |

These are documented, not hidden; each loses one image (8 → 7). The cause is small validation
pools (oven = 11) split four ways. Flipping `subset.pool: train+val` would fill them (≈2489-image
pool, no leakage since the study is zero-shot).

**Id-list schema (one record per selected image):** `image_id`, `coco_id`, `target_category`,
`condition`, `split`, `n_subjects`, `object_count`, `clutter_bin`, `stratum`; TP adds `bbox`,
`eccentricity`, `ecc_bin`.

**Standalone export** ([`scripts/export_subset.py`](../scripts/export_subset.py)): `data/subset/`
(105 MB) materializes the actual images + filtered human scanpaths (raw schema) + id lists +
manifest + config + README, and `data/gazeagent_subset.tar.gz` (103 MB) packages it. A
read-only self-containment check confirmed: every id-list image present, fixation keys match
the id lists exactly, 10 subjects/image, no orphan files, no external references.

## 7. Analysis of the subset

Descriptive characterization of the **human reference data** and the stratification variables.

### 7.1 Search efficiency — scanpath length

![Scanpath length](../figures/fig_scanpath_length.png)

| condition | median | mean | p90 | p99 | max |
|---|--:|--:|--:|--:|--:|
| TP | 3 | 3.79 | 6 | 14 | **34** |
| TA | 5 | 6.03 | 11 | 20 | **45** |

TP searches are short — humans typically find a present target in ~3 fixations. TA searches are
longer and heavier-tailed: confirming *absence* takes more looking. The subset human scanpath
maxima are **34 (TP)** and **45 (TA)** fixations.

### 7.2 Accuracy, reaction time, target size

| metric | TP | TA |
|---|--:|--:|
| accuracy (correct response) | 92.3% | 93.2% |
| reaction time (median / p90 ms) | 683 / 1370 | — |
| target area (% of image, median) | 3.7% | n/a (absent) |
| fixation-on-target rate | — | 0.0% (sanity: target truly absent) |

![TP target size](../figures/fig_target_size.png)

Targets are small (median 3.7% of the image, 90th percentile 7.8%), consistent with a genuine
search task rather than a trivially salient one.

### 7.3 Spatial signature — eccentricity, clutter, saccades, centre bias

![TP eccentricity](../figures/fig_eccentricity.png)
![Clutter](../figures/fig_clutter.png)
![Saccade amplitude](../figures/fig_saccade_amplitude.png)
![Initial fixation density](../figures/fig_initial_fixation.png)

- **Eccentricity (TP):** median 0.35 (normalized distance from centre); the per-category-median
  split yields balanced near/far cells.
- **Clutter:** TP median 6 objects (max 44), TA median 8 (max 32) — TA scenes skew busier,
  plausibly because target-absent images of cluttered scenes are abundant.
- **Saccade amplitude:** median 0.122 (TP) / 0.140 (TA) of the image diagonal; longer saccades
  under absence are consistent with broader coverage.
- **Centre bias:** initial fixations cluster tightly at (≈815, 510) px vs. the (840, 525)
  image centre — the expected forced-central-start signature of the recording protocol.

## 8. Design choices & rationale

| Choice | Decision | Why / alternative rejected |
|---|---|---|
| Evaluation pool | **Validation split** | Test fixations are withheld upstream → "test only" is impossible; validation is the held-out official partition. |
| Train/test leakage | **Not a concern** | The study is **zero-shot** — nothing is trained — so the train/test boundary carries no leakage risk; the constraint is just "frozen + seeded, no cherry-picking." |
| Bin thresholds | **Per-category median** | Guarantees ~50/50 within each category; a global median skewed small categories. |
| Subjects/image | **Exactly 10** | Clean, maximal human↔human agreement ceiling; costs only ~0.5% of images (3 dropped). |
| Clutter measure | **COCO instance count** | The spec's "by object count"; authoritative and reproducible. |
| Coordinate space | **1680 × 1050, normalize x/1680, y/1050** | The frame gaze was recorded in; using native image size would silently corrupt every spatial metric. |
| Human fixation storage | **Raw COCO-Search18 schema (lossless)** | Reuses existing metric code; normalization happens at the loader edge. |
| Under-filled cells | **Log, don't backfill (default)** | Transparency over forced balance; `backfill`/`train+val` available if full 8 needed. |

(Generation-side choices — foveation, the agentic harness, the fixation cap, and inhibition of
return — are **not** part of the dataset; see [experiment_methods.md](experiment_methods.md).)

These respect the dataset-side CLAUDE.md **guardrails**: no dataset resplit; official partition
only; no training/fine-tuning; frozen seeded subset.

## 9. Reproducibility

```bash
# 1. clutter annotations (idempotent; ~241 MB download, ~490 MB extracted)
bash scripts/download_coco_annotations.sh
# 2. frozen stratified subset  -> data/image_ids_{tp,ta}.json + data/subset_manifest.json
python scripts/build_subset.py
# 3. standalone exportable folder + tarball  -> data/subset/ , data/gazeagent_subset.tar.gz
python scripts/export_subset.py
# 4. analysis + figures (offline, no model calls)  -> figures/*.png + figures/analysis_stats.json
python scripts/analyze_subset.py
```

- **Seed 0** throughout; `build_subset.py` is deterministic (re-run → byte-identical id lists).
- **Committed:** `config.yaml`, `data/image_ids_*.json`, `data/subset_manifest.json`,
  `scripts/`, `docs/`, `figures/`. **Gitignored** (regenerable / large): `data/images/`,
  `data/coco_annotations/`, `data/human_fixations/`, `data/subset/`, the tarball, `raw_data/`.

## 10. Limitations & open items

- **Small-category underfill** — bowl/laptop/oven yield 7 TP images; switch to `train+val` for
  a full 144 if needed.
- **Validation, not test** — an upstream constraint, not a choice; stated for transparency.
- **Scope** — this report covers only the dataset (image subset + human reference scanpaths).
  The agent-data generation (foveation, harness, inhibition of return, fixation cap) and the
  eventual human-vs-agent comparison are a separate stage; see
  [experiment_methods.md](experiment_methods.md). No agent results are presented here.
